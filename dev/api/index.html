API

These are the internal building blocks of the Ferrite backend. The PDESystem front end is documented on the Discretization page.

Meshes

rectangle_grid(celltype, cells::NTuple{N, Int}; lo = zeros(N), hi = ones(N))

Ferrite.generate_grid on the box [lo, hi] (default the unit box, not Ferrite's [-1, 1]^N) with the boundary facet sets named as DomainSets names the box faces: "bottom", "right", "top", "left" in 2D and "x1_lo", "x1_hi", "x2_lo", … in every other dimension. No other facet sets are kept.

FiniteElementMethod.check_facetsets — Function
check_facetsets(grid, names; disjoint = true)

Validate the facet sets that boundary conditions refer to (spec §4.6, §6.1): every name must be a facet set of grid, no facet may lie in two of the named sets (unless disjoint = false), and a set containing interior facets (shared by two cells) is an error, since a boundary piece lies on the boundary. Returns nothing.

Discrete space

FiniteElementMethod.FEMSpace — Type
FEMSpace(grid, fields; dirichlet = (), quadrature = nothing, t0 = 0.0, regions = Dict(), hessians = false)

The Ferrite discrete space of a mesh discretization (spec §6.2-6.4). fields is an ordered collection of name => interpolation pairs; after renumber!(dh, DofOrder.FieldWise()) field k occupies a contiguous block of the global dof vector, in declaration order. dirichlet is a collection of (field, facetset_name, g) with g(x, t). quadrature is the quadrature order shared by every field, 2p for the highest Lagrange order p by default (spec §5.6). The constraint handler is first updated at t0, the initial time, since Dirichlet data need not be defined before it.

regions maps a field name to the name of a cell set of the grid: the field then lives only on those cells (spec §6.2), through one SubDofHandler per distinct set of fields present on a cell. Fields not in regions live on every cell. hessians = true builds the CellValues with update_hessians = true, which the SUPG kernels need.

Fields: grid, dh (the DofHandler), ch (the closed ConstraintHandler), fields (names in declaration order), cellvalues and facetvalues (NamedTuples keyed by field), ranges (global dof range per field), pieces (piece name => facet set name, for every facet set of the grid) and pattern (allocate_matrix(dh, ch), to be copied for every operator).

DAE lowering

FiniteElementMethod.FEMOperators — Type
FEMOperators(M, K, load, fields; prescribed = Int[], dirichlet_values = 0.0, nonlinear = nothing)

Assembled operators of the semi-discrete system M du + K u + N(u, t) = F(p, t), with Dirichlet conditions applied by algebraic row replacement: for each prescribed dof d, row d of M is zeroed, row d of K becomes e_d and F[d] = g_d(t). M and K are copied, not mutated, and must share one sparsity pattern (for example from Ferrite.allocate_matrix(dh, ch)) that contains the diagonal entry of every prescribed dof.

  • load: a vector, or a function (out, t) -> out writing the full load vector. Loads do not see the parameters; parameter-dependent operators are reassembled instead (spec §8.3).
  • fields: name => range pairs in state order; the ranges must tile 1:size(M, 1).
  • dirichlet_values: a number, a vector over prescribed, or (out, t) -> out.
  • nonlinear: nothing, or a FEMNonlinear whose Jacobian has the sparsity pattern of M and K. Its rows at prescribed dofs are dropped, so the Dirichlet rows stay u_d = g_d(t).

The fields M, K, load, fields, prescribed, differential_vars and jac_prototype are read by numeric_dae_problem. differential_vars is false on prescribed dofs and on every row where M is zero, which covers algebraic equations such as 0 ~ Dxx(v) + f.

FiniteElementMethod.FEMOp — Type
FEMOp(A::SparseMatrixCSC)

Opaque wrapper for an assembled operator, used as a non-tunable System parameter so that ModelingToolkit neither flattens it into the tunable vector nor scans it element by element. A keeps its floating-point element type; any other matrix is converted to SparseMatrixCSC{Float64, Int}.

source
FiniteElementMethod.FEMLoad — Type
FEMLoad

The right-hand side F(t) of M du + K u = F with the Dirichlet rows F[d] = g_d(t). timedep is true when the volume load or the Dirichlet data is a function. It holds no buffers: load! writes into the caller's vector, so problems that share a FEMLoad (remakes, ensembles) never share mutable state through it.

source
FiniteElementMethod.FEMNonlinear — Type
FEMNonlinear(op, p)

Opaque wrapper for the nonlinear part N(u, t) of M du + K u + N(u, t) = F(t), used as a non-tunable System parameter like FEMOp: op is a NonlinearOperator and p the parameter values its kernels are evaluated with. FEMOperators marks the prescribed dofs, whose rows of N and of its Jacobian are then zero. op is untyped so that the parameter has one concrete type; each call dispatches on it once. op itself is never evaluated: each evaluation borrows a copy with its own buffers and values objects from a pool, so problems sharing this wrapper (remakes, ensembles) can be solved concurrently. After eliminate_dirichlet the wrapper evaluates N at the full state rebuilt from the free dofs with u_d = g_d, and keeps its free rows and its [free, free] Jacobian block.

N is evaluated at AbstractFloat states, such as Float64 or Float32, and at first-order ForwardDiff.Duals of those (as the default initializer passes), whose partials go through the analytic tangent; the element buffers of op keep their own element type, Float64 from NonlinearOperator. Any other state, such as nested Duals, throws ArgumentError("the nonlinear operator evaluates AbstractFloat states and first-order ForwardDiff Duals of them; got T") with T the state's element type; its Jacobian is evaluated at AbstractFloat states only and otherwise throws ArgumentError("the nonlinear operator's Jacobian evaluates AbstractFloat states; got T"). p keeps a floating-point element type and is converted to Float64 otherwise.

FiniteElementMethod.fem_system — Function
fem_system(ops::FEMOperators, iv; unknowns = nothing, metadata = nothing, name = :fem)

The completed array-residual System: one array unknown per field, the operators as opaque non-tunable parameters Mop, Kop, Fop (and Nop for ops.nonlinear), and one block equation per field, F_i(p, t) ~ Σ_j M_ij D(u_j) + K_ij u_j (+ N_i(u, t)). parameters are symbol => value pairs added as parameters with those values, which the operators were assembled with. unknowns defaults to name(iv)[1:n] per field. Returns (sys, unknowns, parameter_map).

FiniteElementMethod.numeric_dae_problem — Function
numeric_dae_problem(ops::FEMOperators, u0, tspan, metadata = nothing;
    iv = ModelingToolkit.t_nounits, unknowns = nothing, du0 = nothing,
    initializealg = BrownFullBasicInit(nlsolve = NewtonRaphson(autodiff = AutoForwardDiff())),
    coordinate = nothing, name = :fem, kwargs...)

Build the DAEProblem for M du + K u + N(u, t) - F(p, t) = 0 with a numeric residual, an analytic sparse Jacobian K + γ M + ∂N/∂u and the completed System of fem_system attached for symbolic indexing. No initialization problem is built and nothing calls mtkcompile.

parameters (symbol => value pairs) become parameters of the System at the values the operators were assembled with; the residual and Jacobian throw an ArgumentError naming the parameter if a remake has changed one. metadata becomes the problem's problem_type; a SciMLBase.AbstractDiscretizationMetadata first gets the System through PDEBase.add_metadata!. du0 defaults to the consistent one of consistent_du0. coordinate(dof) is used in the error for a non-finite u0. Remaining keywords are passed to DAEProblem.

source
FiniteElementMethod.consistent_du0 — Function
consistent_du0(ops::FEMOperators, u0, t0)

du0 with du_d = g'(t0) on prescribed dofs, zero on the other algebraic rows, and M_ff du_f = (F(t0) - K u0 - N(u0, t0) - M_fd g'(t0))_f on the differential rows. Throws an ArgumentError when a non-prescribed algebraic variable has a nonzero column in M: its du is then not zero, cannot be found without index reduction, and must be passed as du0. The zero on a non-prescribed algebraic row is by contract: the residual does not define the derivative of an algebraic variable, and the solution and its dense output do not depend on it.

source
FiniteElementMethod.eliminate_dirichlet — Function
eliminate_dirichlet(ops::FEMOperators) -> (reduced::FEMOperators, elimination)

Restrict ops to its free dofs fr (spec §7.3): M[fr, fr], K[fr, fr] and the load F[fr] - K[fr, cd] g for the prescribed dofs cd. The Dirichlet data g must be constant in time, so g' = 0 and the term M[fr, cd] g' vanishes; time-dependent data, and operators with every dof prescribed, throw an ArgumentError. The field ranges of reduced count free dofs only, and a field whose dofs are all prescribed is left out of them; full_state(elimination, u_free) rebuilds the full dof vector with u[cd] = g. A nonlinear part N is kept: it is evaluated at that full vector, with its rows fr and its Jacobian block [fr, fr].

source
FiniteElementMethod.check_finite_initial_condition — Function
check_finite_initial_condition(u0, fields; coordinate = nothing)

Throw an ArgumentError naming the first dof of u0 that is not finite, its field and, if coordinate(dof) is given, its node coordinate. A non-finite initial value (for example sin(r)/r at r = 0) would otherwise give a NaN du0 and an Unstable return at step 1.

FiniteElementMethod.FieldInfo — Type
FieldInfo(dv, name::Symbol, unknown, ip::Ferrite.Interpolation)

One dependent variable of a FEM discretization: the PDESystem dependent variable dv (for example u(t, x, y)), the name of its field in the DofHandler, the array unknown of the discretized system (for example u(t)[1:n], or nothing for a field that dirichlet = :eliminate prescribes entirely) and the field's interpolation.

FiniteElementMethod.FEMMetadata — Type
FEMMetadata(space, time, x̄, fields, pieces, pdesys; u0 = Float64[], elimination = nothing)

Discretization metadata passed as the problem_type of the DAEProblem (or, for a steady problem with time === nothing, the NonlinearProblem), so that solve returns a SciMLBase.PDETimeSeriesSolution (or SciMLBase.PDENoTimeSolution) that is indexed and called in the variables of the PDESystem.

  • space: the discrete space; only space.dh::Ferrite.DofHandler is used.
  • time: the time independent variable, or nothing for a steady problem.
  • x̄: the spatial independent variables in the order of the (x, y) ∈ Ω pairing; position i is coordinate component i of the mesh.
  • fields: one FieldInfo per dependent variable.
  • pieces: maps each boundary piece to the name of its Ferrite facet set.
  • pdesys: the PDESystem that was discretized.
  • elimination: nothing, or for dirichlet = :eliminate the data that rebuild the full dof vector from the solver's free dofs, so every accessor returns full fields.

FiniteElementMethod.piece_nodes — Function
piece_nodes(sol, Γ)

Sorted vertex ids of the boundary piece Γ. They are the columns of sol[u(t, Γ)] and sol(t, Γ; dv) (the rows of sol[u(Γ, t)] for a time-last u(x, y, t)), and they index sol[x], so sol[x][piece_nodes(sol, Γ)] are the coordinates of the trace values.

FiniteElementMethod.normal_flux — Function
normal_flux(sol, dv, Γ)

Facet-mean outward normal derivative ∇u·n of the field dv on every facet of the boundary piece Γ, nt × nfacets (nfacets × nt for a time-last u(x, y, t), a vector for a steady solution). Facets are ordered by (cell, local facet). This is a post-processed flux, not the imposed boundary datum.

FiniteElementMethod.write_vtk — Function
write_vtk(sol, base::AbstractString) -> String

Write one .vtu file per saved time, "$(base)_0001.vtu" and so on, with every field as point data, plus a ParaView collection "$(base).pvd" that maps them to sol.t. Returns the path of the .pvd file. A steady solution is written to the single file "$(base).vtu", whose path is returned.

source
FiniteElementMethod.facet_dofs — Function
facet_dofs(md::FEMMetadata, Γ, field) -> Vector{Int}

Sorted global dof indices of field on the boundary piece Γ (a piece of the discretization, or a facet-set name as String or Symbol): every dof whose basis function is nonzero on a facet of Γ, so for order 2 the mid-edge dofs as well as the vertices. field is the field name or its dependent variable. These are the rows a boundary term on Γ enters, and the trace of the field on Γ is determined by the values there. A field that lives in no cell next to Γ (a field on a region) has no dofs there, and the result is empty.

source
FiniteElementMethod.dof_coordinates — Function
dof_coordinates(md::FEMMetadata) -> Matrix{Float64}

dim × ndofs matrix whose column d is the coordinate of global dof d (Lagrange dofs are nodal, so the field's value at that point is the dof value). Dofs of a field restricted to a region have coordinates only where the field lives; this covers every dof of every field.

source
FiniteElementMethod.cell_dofs — Function
cell_dofs(md::FEMMetadata, field) -> Matrix{Int}

nbasis × ncells matrix of the global dofs of field in each cell, in the local order of the field's interpolation (vertices first, as Ferrite numbers them). A discretization with regions throws, since its fields do not live on every cell.

FiniteElementMethod.KernelSpec — Type
KernelSpec(eq, kind, piece, f, tangent, coeffs = nothing)

Quadrature-point kernel f(U, G, Ud, V, W, X, T, N, P) of equation eq; piece is nothing for volume kernels and tangent is nothing unless kind === :nonlinear.

coeffs, for the linear kinds, lets the driver contract coefficients with the shape functions once per quadrature point instead of calling f per test and trial function; f may then be nothing. Called as coeffs(X, T, N, P), it returns a tuple indexed by (s - 1) * (1 + dim) + w for the test slots w in [V; W]:

  • :source: ∂I/∂w (one trial "slot");
  • :bilinear: ∂²I/∂s∂w for the trial slots s in [U; G];
  • :mass: ∂²I/∂s∂w for the trial slots s in Ud.

Entries may be StructuralZero(), which the driver drops at compile time.

FiniteElementMethod.classify — Function
classify(integrand, slots, test)

Split the expanded integrand into additive terms and bucket each as :source (no state slot), :bilinear (every derivative with respect to a state slot is state-free) or :nonlinear. State slots are the declared slots.U, slots.G and slots.H (if present). Returns (kind, integrand, timedep, paramdep) named tuples, one per non-empty bucket, where timedep means the bucket contains slots.T and paramdep that it contains a parameter slot of slots.P.

source
FiniteElementMethod.state_slots — Function

The declared state slots of slots: U, G and, when the slot set has one, H.

source
FiniteElementMethod.weak_form — Function
weak_form(analysis; test = TestSlots(analysis.dim), test_space = Galerkin())

Projection of a strong-form analysis: equation e contributes mass[e]·V (kind :mass), the integrated-by-parts volume integrand −G·W + R·V, and Φ·V on each natural condition's piece. With SUPG, the volume integrand gains τ (b·W)(strong[e] − mass[e]) and the mass term mass[e]·τ (b·W).

source
FiniteElementMethod.emit_kernels — Function
emit_kernels(wf::WeakForm; coeffs = true, expression = Val(false))

One KernelSpec per equation, kind and piece of wf (the terms sharing them are summed), as a tuple. Linear kinds carry coeffs, the coefficient form the driver contracts with the shape functions, and then no f (see compile_coeffs for the exceptions). :nonlinear kernels carry f(U, G, Ud, V, W, X, T, N, P), the scalar integrand, and tangent, with the same arguments, returning the tuple ∂I/∂[U; G] (length nf + nf*dim). coeffs = false emits f for every kernel instead. Array slots accept Vec, tuples or vectors.

expression = Val(true) returns the same KernelSpecs with the generated Expr in place of each function, for inspecting or diffing the generated code; evaluating an Expr gives the function the default call compiles.

FiniteElementMethod.AssemblyContext — Type
AssemblyContext(dh, fields, cellvalues, facetvalues, pieces = Dict())

What the driver needs to assemble kernels: the DofHandler, its field names in equation/field index order, the CellValues and FacetValues of each field, and pieces, a map from boundary piece to its facet set, given as a facet-set name of the grid or as a set of FacetIndex.

cellvalues and facetvalues are each a NamedTuple keyed by field name, a tuple in field order, or a single values object shared by all fields. The values of all fields must use one quadrature rule (the same points in the same order, and weights), since test and trial functions of different fields are paired by quadrature point. A field may be missing from some SubDofHandlers of dh (a field on a region): there it has no dofs, its equation is not assembled and its state slots are zero.

Each facet set is copied at construction, so changing the caller's set or the grid's facet sets afterwards does not affect the context; build a new one instead.

FiniteElementMethod.assemble_linear — Function
assemble_linear(ctx, kernels, p; t = 0.0, ch = nothing) -> (; M, K, F)

FiniteElementMethod.SUPG — Type
SUPG(τ; b = nothing)

Streamline-upwind Petrov–Galerkin testing: the Galerkin form plus τ (b·∇v) times the strong residual on every cell, with the mass term tested by v + τ b·∇v too. b is the advection velocity, by default read from the analysis as the coefficient of the equation's own gradient in its remainder, b_d = ∂R/∂(∂_d u), which must be free of the state (otherwise pass b, a vector of numbers or expressions). τ is a number, an expression, or a function τ(hK, b) of the element size hK and b, e.g. (hK, b) -> hK / (2 * sqrt(sum(abs2, b))). An equation whose b is zero is tested with Galerkin. Boundary terms stay Galerkin. The stabilised terms need the Hessian slots H and hK, so the driver's CellValues must be built with update_hessians = true.

source
FiniteElementMethod.emit_strong — Function
emit_strong(analysis; expression = Val(false))

The strong residual e = lhs − rhs of each equation as a function r(U, G, Ud, H, X, T, P), for collocation (test function δ, spec §1 goal 4): it vanishes at the exact solution.

source
FiniteElementMethod.compile_coeffs — Function
compile_coeffs(kind, ex, slots, test)

The coefficient form of a :mass, :bilinear or :source integrand ex (see KernelSpec), or nothing, in which case the kernel keeps the per-shape-function f. It is nothing when

  • kind is :nonlinear: per quadrature point the coefficients cost more than calling f and tangent per test function (measured on case (iii), 1.43× against 1.20× of hand-written);
  • ex is not the sum of its coefficients times the trial and test slots, e.g. a term with a part free of the trial slots or of the test slots, or one nonlinear in them;
  • a coefficient depends on a trial or test slot, i.e. on U, G, Ud, H, V or W.

Terms built by weak_form always have a coefficient form; the fallback serves hand-built integrands. A term with the Hessian slots H or the element size hK (the stabilised terms of SUPG) gets a CellCoeffs.

source
FiniteElementMethod.CellCoeffs — Type
CellCoeffs(f, fields)

A coeffs function that needs the element: called as f(X, T, N, P, hK) with the element size hK, and for a :bilinear kernel its trial slots are [U; G; H], with the Hessian slots H contracted with the shape-function Hessians of each field. fields lists the fields whose Hessian slots the coefficients use, whose values must therefore carry Hessians. Built for the stabilised terms of SUPG; plain coeffs keep (X, T, N, P) and [U; G].

Precompilation

FiniteElementMethod.workload_chain — Function
workload_chain(k = 2.0; nel = 2)

Build and assemble ∂ₜu = ∇·(k∇u) − u³ + xy + 1 with k∇u·n = k·P₁ on right, from a hand-built strong-form analysis (no PDEBase) on an nel × nel triangle grid: weak_form, emit_kernels, assemble_linear and one residual!. The precompile workload runs it; a different k generates different kernels, which is how the cold-latency gate measures time to first assembly without reusing the workload's own kernels.
