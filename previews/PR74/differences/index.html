Differences from MethodOfLines

A PDESystem for FiniteElementMethod.jl is an ordinary ModelingToolkit PDESystem, and most of it reads as it does for MethodOfLines. This page lists, in order, the places where a mesh makes the package behave differently from what a MethodOfLines user expects.

Coordinate binding

Read this first

A MeshDomain carries no coordinate names. The names and their order come only from the (x, y) ∈ Ω pairing in the domains of the PDESystem: tuple position i is coordinate component i of the mesh.

  • The tuple must have one entry per mesh coordinate, which is the mesh's spatial dimension; for a surface mesh embedded in 3D it is the embedding dimension 3. A mismatch is an error when the system is discretized: domain MeshDomain of a … mesh has 3 coordinates but the pairing names 2.
  • The order of the pairing, not the argument order of the dependent variables, decides which name is which mesh coordinate: with (y, x) ∈ Ω and u(t, x, y), y is mesh coordinate 1 and x is mesh coordinate 2.
  • The same pairing orders sol[x] and sol[y] (the node coordinates) and the spatial arguments of sol(t, x, y).
  • Trace and NormalDerivative conditions never mention coordinate names, so they need none. The spatial variables appear only in the equations, in initial conditions such as u(0, x, y) ~ x * y, and in data such as u(t, Γ) ~ x * sin(t).

Trace syntax

A boundary condition is an equation on the trace of a dependent variable on a named boundary piece Γ, a facet set of the mesh obtained from boundarypiece(Ω, :name).

  • The piece replaces exactly the spatial arguments. For u(t, x, y) the trace is u(t, Γ): time stays explicit and in its declared position, as in MethodOfLines' u(t, 0, y). Every other argument is unchanged.
  • u(Γ) is an error on a time-dependent problem. The message shows the form to write: u(Γ_left): trace is missing the time argument; write u(t, Γ_left). u(Γ) is the trace only on a steady problem whose dependent variables have no time argument, such as u(x, y) (see Steady problems).
  • Dn_Γ(u(t, Γ)) is the trace of the normal derivative, where Dn_Γ = NormalDerivative(Γ): differentiate along the outward unit normal of Γ, then evaluate on Γ. This is the reading of MethodOfLines' Dx(u(t, 0, y)). Write a conormal coefficient explicitly, as in k * Dn_Γ(u(t, Γ)) ~ h for the flux k ∇u.
  • The operator's piece must match the trace's piece. NormalDerivative(Γa)(u(t, Γb)) with Γa ≠ Γb is an error when the system is discretized.
  • The MethodOfLines endpoint form is not accepted on a mesh. A mesh domain has no coordinate intervals, so u(t, 0, y) ~ 0 cannot name a face even when the mesh is a box; write a trace on a boundary piece instead.
  • Pieces on a mesh broadcast; pieces on an analytic box need Ref. boundarypiece.(Ω, (:inlet, :wall)) works for a MeshDomain. On an analytic DomainSets box, such as a Rectangle in a system also given to MethodOfLines, write boundarypiece.(Ref(rect), (:left, :right)), because DomainSets domains do not broadcast as scalars. A rectangle's pieces are named :bottom, :right, :top, :left. FEMDiscretization itself needs a MeshDomain.

Solution shapes that differ from MethodOfLines

solve returns a SciMLBase.PDETimeSeriesSolution whose metadata is a FEMMetadata. It is indexed and called in the variables of the PDESystem, like a MethodOfLines solution, with these differences.

  • sol[x] is the vector of mesh node coordinates, not an axis grid. For a mesh of linear cells the nodes are the vertices. Tensor-grid plotting calls such as heatmap(sol[x], sol[y], …) fail with a shape error; resample with sol(t, xs, ys; dv = u(t, x, y)) instead, which gives the tensor product of xs and ys.
  • sol[u(t, x, y)] is nt × nnodes (nnodes × nt for u(x, y, t)), and node i pairs with (sol[x][i], sol[y][i]). It is the field evaluated at the mesh nodes, so for a P2 field the edge dofs are not included. sol[u(t, x, y), k, :] is the row at t_k.
  • The time axis goes first or last according to the declared argument order of each dependent variable, as in MethodOfLines. For a time-last u(x, y, t) every array keyed by that field is transposed, nnodes × nt (the trace sol[u(Γ, t)], the gradient sol[Differential(x)(u(x, y, t))] and normal_flux too), and calls take the time last: sol(x, y, t; dv), sol(Γ, t; dv), sol(pts, t; dv). With vector arguments sol(xs, ys, ts; dv) is length(xs) × length(ys) × length(ts). Fields of one system may differ; sol(args...) without dv then throws, because the position of the time argument is ambiguous. Time between two spatial arguments, u(x, t, y), is rejected by discretize.
  • The raw dof coefficients are in sol.original_sol, the solution of the DAEProblem; sol.original_sol.u[k] is the dof vector at t_k.
  • Points outside the mesh return NaN by default, which a non-convex mesh needs, since any resampling grid has points outside it. sol(t, x, y; dv, outside = :error) throws a DomainError instead.
  • A time outside the saved span throws a DomainError; the DAE interpolation is never extrapolated.
  • sol(t, x, y; dv) interpolates the dof vector in time and evaluates it at the points. Vector arguments give a tensor product and scalar arguments drop their axis; sol(t, pts::Vector{<:Vec}; dv) evaluates at scattered points, and sol(t, x, y) with no dv returns one value per dependent variable.
  • Only first spatial derivatives are accepted as keys. sol[Differential(x)(u(t, x, y))] is the cellwise gradient L2-projected onto the field's space and read at the nodes, and sol(t, x, y; dv = Differential(x)(u(t, x, y))) is the pointwise gradient. Higher derivatives are an error naming the accepted keys.
  • Traces. sol[u(t, Γ)] is nt × length(piece_nodes(sol, Γ)); piece_nodes also indexes sol[x]. sol(t, Γ; dv) is the trace at time t.
  • sol[Dn_Γ(u(t, Γ))] is a post-processed flux, not the imposed datum. It is the facet-mean outward normal derivative ∇u·n on each facet of Γ, nt × nfacets, the same as normal_flux. It converges to the boundary datum under refinement but does not equal it on a given mesh.
  • write_vtk(sol, base) writes one .vtu file per saved time and a ParaView collection base.pvd.

Observed expressions

sol[expr] evaluates an expression in the dependent variables, their first spatial derivatives, the independent variables and the parameters of the PDESystem, for example sol[u(t, x, y)^2 + k * v(t, x, y)], sol[2u(t, x, y)] or sol[x^2 + y]. It has the shape of sol[u(t, x, y)], nt × nnodes (a vector for a steady solution), even when the expression names only coordinates. sol(t, xs, ys; dv = expr) and sol(t, Γ; dv = expr) evaluate it at points or on a boundary piece, with the shapes of a field, and NaN outside the mesh.

The time axis follows the expression's dependent variables, as for a field: an expression in time-last variables, sol[u(x, y, t)^2], is nnodes × nt and is called as sol(xs, ys, t; dv = expr). An expression with no dependent variable follows the system's variables. An expression that mixes time-first and time-last variables, or names none in a system that mixes them, throws an ArgumentError: evaluate the parts separately.

  • The expression is compiled once with build_function and broadcast over the vertex values of its leaves; nothing is substituted per vertex. A first derivative such as Differential(x)(u(t, x, y)) uses the same values as sol[Differential(x)(u(t, x, y))].
  • A parameter takes the value given in the PDESystem, as k => 2.0; the front end has assembled the operators with that value, so remake with a new one does not change it.
  • An expression that cannot be evaluated throws an ArgumentError beginning "cannot evaluate the expression … on this solution:", which names a variable that is not of the system, a trace u(t, Γ) (index the trace on its own, or pass Γ to the call instead), a derivative that is not a first spatial derivative, or a dependent variable at fixed arguments such as u(t, 0, y).
  • A dependent variable at fixed arguments, such as u(t, 0, y) or u(0, x, y), is rejected wherever a dependent variable is accepted (sol[…], dv, derivatives, normal_flux) with the ArgumentError "u(t, 0, y) fixes arguments of u(t, x, y); write the dependent variable as u(t, x, y)"; a mesh has no coordinate lines to restrict to. A trace keeps time and replaces the coordinates by one piece, u(t, Γ) or u(Γ, t).
