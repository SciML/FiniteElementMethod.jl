Discretization

FEMDiscretization, Galerkin, SUPG and add_boundary_pieces! are exported, as are the PDEBase names a model needs (MeshDomain, Region, boundarypiece, boundarypieces, NormalDerivative) and Ferrite's Lagrange and reference shapes. Getting started shows them in use.

FiniteElementMethod.FEMDiscretization — Type
FEMDiscretization(Ω::MeshDomain, t = nothing; spaces = Dict(), regions = Dict(),
    quadrature = nothing, test_space = Galerkin(), ibp = Dict(), pairing = Dict(),
    codegen = :numeric, dirichlet = :algebraic, algebraic_abstol = :auto, natural = (), boundary_check = :warn, kwargs...)

Finite-element discretization of a PDESystem whose spatial domain is the mesh domain Ω (of a Ferrite.Grid), with time variable t. discretize(pdesys, disc) assembles the Galerkin operators with Ferrite and returns a DAEProblem with one array unknown per field. Without t the discretization is steady: the PDESystem must have no time variable, and discretize (or NonlinearProblem(pdesys, disc)) returns a NonlinearProblem whose solve gives a PDENoTimeSolution.

  • spaces: dependent variable (u or u(t, x, y)) => Ferrite.Interpolation; the default is Lagrange{RefShape, 1}() on the mesh's reference shape. Fields may have different orders, such as the Taylor–Hood pair Lagrange{RefTriangle, 2}() for the velocity and Lagrange{RefTriangle, 1}() for the pressure. The geometry is not a choice here: cells are mapped with the geometric interpolation of the mesh's cell type, so a mesh of quadratic cells (QuadraticTriangle, say, from a second-order Gmsh mesh) is mapped isoparametrically.
  • regions: dependent variable => Region(Ω, name), a cell set of the mesh on which the field lives (a Ferrite.SubDofHandler); elsewhere it has no dofs, its equation is not assembled, it enters other equations as zero and the solution reads NaN. Its conditions must be on pieces whose facets belong to the region's cells.
  • quadrature: quadrature order shared by all fields; nothing means 2p for the highest Lagrange order p.
  • test_space: Galerkin() or SUPG(τ; b), streamline-upwind Petrov–Galerkin stabilisation of every equation; linear terms only, and τ cannot reference parameters.
  • ibp: equation (or its index) => PDEBase.StrongForm integration-by-parts policy.
  • pairing: equation => dependent variable it is tested with, needed for an equation with no time derivative of its own, such as 0 ~ Dxx(v) + f. In a steady system the equations not named here take the remaining dependent variables in declared order.
  • natural: boundary pieces (as boundarypiece(Ω, name) or a facet set name) that deliberately carry the natural zero-flux condition of every field, such as an outflow or a symmetry plane. A piece with an explicit zero Neumann condition Dn(u(t, Γ)) ~ 0 needs no entry here. See boundary_check.
  • boundary_check: what to do when part of the boundary has no condition for a field whose equation has a flux, neither a Dirichlet, Neumann or Robin condition nor a natural piece. :warn (default) logs one warning per discretize call, listing the pieces and the number of facets for each such field, and treats them as zero-flux; :error throws the same message as an ArgumentError, for strict completeness; :off skips the check. A facet claimed by two pieces that both carry conditions, and a piece that is not on the boundary, are errors whatever boundary_check is. A boundary given as a lower-dimensional mesh is made a piece with add_boundary_pieces!.
  • algebraic_abstol: the absolute tolerance the DAEProblem carries for its algebraic rows (those with differential_vars false: algebraic fields and Dirichlet rows), so that they are left out of the solver's error control. :auto sets 1e8 when the system has index 2, that is when an algebraic field's own unknowns are absent from its equation (the pressure in 0 ~ Dx(u1) + Dy(u2); a nonlinear term in the field, as in 0 ~ v^2 - u, counts as present), and nothing otherwise; a positive number sets that value on the algebraic rows of any system; nothing sets nothing. The differential rows get the abstol passed to FEMDiscretization or DAEProblem if it is a number, else OrdinaryDiffEq's default 1e-6; an array abstol passed there is used as it is. An abstol passed to solve replaces the problem's whole vector. The keyword belongs to the time-dependent (DAE) path: a steady discretization ignores :auto and nothing and rejects a number. This keyword is not in the spec (§7.1, §7.6): without it, DFBDF drives the step size of an index-2 system below eps near the initial time, since the local error of the index-2 unknowns does not shrink with the step.
  • dirichlet: how Dirichlet conditions enter the DAE (spec §7.3). The default :algebraic keeps every dof as an unknown and makes each prescribed row the algebraic equation u_d = g_d(t). :eliminate removes the prescribed dofs: the unknowns are the free dofs fr, the operators are M[fr, fr] and K[fr, fr] and the load is F[fr] - K[fr, cd] g; nonlinear terms are evaluated at the full state with u_cd = g and keep their rows fr. It needs Dirichlet data that are constant in time (they may vary in space); data that depend on time raise ArgumentError("dirichlet = :eliminate needs Dirichlet data that are constant in time, but the condition on boundary piece <name> depends on time; use the default dirichlet = :algebraic") from discretize. A field whose dofs are all prescribed has no array unknown (its FieldInfo.unknown is nothing); if every dof of the problem is prescribed, discretize raises ArgumentError("dirichlet = :eliminate leaves no unknowns because every dof is prescribed; use the default dirichlet = :algebraic"). The solution still returns full fields, with g at the prescribed nodes, through sol[u], sol(t, x, y), traces and write_vtk; only sol.original_sol and the array unknowns hold the free dofs alone. :algebraic is recommended.
  • codegen = :mtk is reserved and raises; remaining keywords are passed to the DAEProblem (or NonlinearProblem), where a keyword given at the discretize call wins. iv, unknowns, du0, coordinate, name and parameters are set by the discretization and rejected, as are tspan, u0, p and differential_vars, which come from the PDESystem and the weak form.

Pieces come from boundarypiece.(Ω, names); on an analytic DomainSets box write boundarypiece.(Ref(rect), names), since DomainSets types do not broadcast as scalars.

Where pieces with Dirichlet conditions on the same field meet (a corner), the condition listed last in the PDESystem's boundary conditions wins, as in Ferrite's ConstraintHandler. Listing the same piece and field twice is an error. Fields are numbered in one order throughout (DofHandler blocks, array unknowns, FEMMetadata.fields), the declared order of the PDESystem's dependent variables (PDEBase.StrongForm.declared_fields); equations are paired with fields through PDEBase.StrongForm.pair_equations.

Parameters are substituted by the values given in the PDESystem when the operators are assembled, and are parameters of the problem at those values. The operators are not reassembled for new values: after remake(prob; p = [k => 3.0]) the solve throws an ArgumentError naming k; build a new problem with discretize(pdesys, disc) instead.

SciMLBase.discretize — Method
discretize(pdesys::PDESystem, disc::FEMDiscretization; kwargs...)

Discretize pdesys with disc and return the DAEProblem M du + K u + N(u, t) = F(t) of the Galerkin operators, with Dirichlet rows u_d = g_d(t) as algebraic equations (or, with dirichlet = :eliminate, restricted to the free dofs), a sparse analytic Jacobian (the nonlinear part N from the terms whose coefficients depend on the state, with its symbolic tangent) and the FEMMetadata as its problem_type, so solve returns a PDETimeSeriesSolution (SciMLBase.wrap_sol of the solver's solution). Nothing calls mtkcompile; anything it cannot discretize raises. A disc without a time variable lowers instead to the steady NonlinearProblem documented under NonlinearProblem(pdesys, disc). Keywords are passed to the DAEProblem after disc.kwargs, so a keyword given here wins; the keywords the discretization sets (iv, unknowns, du0, coordinate, name, parameters) are rejected, and so are tspan (the PDESystem's time domain), u0 (its initial conditions; use remake(prob; u0)), p (its parameter defaults) and differential_vars (computed from the weak form). The problem carries an abstol vector when disc.algebraic_abstol applies (see FEMDiscretization). Any other SciML problem or solver keyword (saveat, tstops, callback, ...) is forwarded. Further positional arguments, a first argument that is not a PDESystem, and an equation, domain or boundary condition the discretization does not support raise an ArgumentError before the operators are assembled. symbolic_discretize returns the symbolic system of the same discretization.

The Dirichlet rows are linear with identity Jacobian rows, so a Newton step with a current Jacobian satisfies them exactly. OrdinaryDiffEq's BDF methods reuse the Jacobian across step-size changes and then rescale the Newton step, which leaves these rows off by about the solver tolerance; DFBDF(nlsolve = NLNewton(new_W_dt_cutoff = 0)) refreshes it on every step size change and holds u(t, Γ) ~ g(t) to round-off.

SciMLBase.NonlinearProblem — Method
NonlinearProblem(pdesys::PDESystem, disc::FEMDiscretization; kwargs...)

Discretize the steady pdesys with a disc that has no time variable and return the NonlinearProblem K u + N(u) - F = 0 of the Galerkin operators, with Dirichlet rows u_d - g_d as algebraic equations, the sparse analytic Jacobian K + ∂N/∂u and the FEMMetadata as its problem_type, so solve returns a PDENoTimeSolution. N holds the terms whose coefficients depend on the state, as on the time-dependent path; without them Newton solves the problem in one step.

The initial guess u0 is zero, with the Dirichlet data g_d wherever the problem's unknown vector holds Dirichlet dofs; a steady PDESystem has no initial conditions. To start Newton elsewhere, remake(prob; u0) with a vector laid out like prob.u0, the problem's unknown vector (with the default dirichlet = :algebraic it holds every dof, and field name occupies FiniteElementMethod.field_range(prob.problem_type.space, name)). Keywords are passed to the NonlinearProblem after disc.kwargs; the keywords iv, unknowns, du0, coordinate, name, parameters, tspan, u0, p and differential_vars are rejected, as for the DAEProblem.

SciMLBase.symbolic_discretize — Method
symbolic_discretize(pdesys::PDESystem, disc::FEMDiscretization; kwargs...)

Return (sys, tspan), the shape PDEBase and MethodOfLines return, for the discretization that discretize(pdesys, disc; kwargs...) builds: it runs the same code path, so it assembles the Galerkin operators, and returns the DAEProblem's prob.f.sys and prob.tspan. sys is the completed ModelingToolkit.System of FiniteElementMethod.fem_system, whose unknowns are the arrays of field values, with the operators as parameters and the FEMMetadata (the problem's problem_type) attached for rebuilding the solution; tspan is the time interval of pdesys. Keywords are passed to that problem construction as for discretize, so the reserved keywords raise the same ArgumentError. Further positional arguments raise an ArgumentError.

A steady disc (no time variable) raises an ArgumentError: its NonlinearProblem is built from a numeric NonlinearFunction with no System, so there is no symbolic system describing it; call discretize(pdesys, disc) for the NonlinearProblem.

FiniteElementMethod.operators — Function
operators(pdesys::PDESystem, disc::FEMDiscretization) -> NamedTuple

The assembled Galerkin operators of discretize(pdesys, disc) as plain data, for a caller that builds its own system around them (such as a component with boundary ports). Returns

  • M, K: the mass and stiffness matrices with one sparsity pattern, before any Dirichlet row is replaced, so a caller can impose its own conditions or read reactions from them;
  • F: the load vector, the volume sources and natural boundary data, without Dirichlet values;
  • fields: name => dof range per field, in declared order;
  • differential_vars: rows of M with a nonzero entry;
  • prescribed, dirichlet_values: the dofs of the PDESystem's Dirichlet conditions and their values (the rows M and K would have replaced);
  • u0: the initial dof vector, with the Dirichlet values on the prescribed dofs. It always has every dof, also under dirichlet = :eliminate, where the DAEProblem's own u0 holds the free dofs only;
  • metadata: the FEMMetadata, for facet_dofs, dof_coordinates and cell_dofs.

It is the linear, time-independent case only, and anything else raises an ArgumentError: a nonlinear term ("operators returns linear operators only, but the PDESystem has nonlinear terms"), a time-dependent source ("operators needs time-independent sources, but a source depends on time") and time-dependent Dirichlet data ("operators needs Dirichlet data that are constant in time"). Parameters are substituted by their values, as for the DAEProblem.

Boundary pieces from submeshes

FiniteElementMethod.add_boundary_pieces! — Function
add_boundary_pieces!(grid, name => submesh, ...; atol = nothing)
add_boundary_pieces!(grid, pieces::AbstractDict; atol = nothing)

Add a boundary piece to the Ferrite.Grid grid for each pair name => submesh: a facet set called name holding the facets of grid that the cells of submesh coincide with. submesh is a Ferrite.Grid of one dimension less than grid, in the coordinates of grid: the boundary mesh that Gmsh gives for a physical group, or any grid whose cells are facets of grid. Afterwards boundarypiece(MeshDomain(grid), name) is the piece, exactly as for any other facet set; grid is modified, as by Ferrite.addfacetset!, and returns.

A submesh cell is matched to a facet of grid through the nodes: each node of the submesh is the node of grid within atol > 0 of it (by coordinates, since the two grids number their nodes independently; the default atol is 1e-8 times the larger of 1 and the largest extent of grid), and the cell is the facet whose corner nodes are those of the cell. Nothing is added, for any of the pieces, if a node has no node of grid within atol, a cell matches no facet of grid, a cell matches an interior facet (shared by two cells) or name is already a facet set of grid; each is an ArgumentError that says which.

source

discretize(pdesys, disc) returns the DAEProblem of the discretization (the NonlinearProblem of a steady one, see Steady problems). symbolic_discretize(pdesys, disc) returns (sys, tspan), where sys is the array-residual System attached to that problem (see FiniteElementMethod.fem_system): one block equation per field over the assembled operators, not scalar equations per node as MethodOfLines returns.

Restrictions of this release:

  • Geometries are Ferrite.Grid meshes (1D, 2D and 3D cell shapes) wrapped as MeshDomain(grid), with boundary pieces named by the grid's facet sets. 1D, 2D and 3D meshes are tested; meshes with mixed cell types are rejected.
  • Coordinates are Cartesian and named by the (x, y) ∈ Ω pairing. Time is the first or last argument of every dependent variable, never between spatial arguments.
  • Dirichlet data may depend on space, time and parameters but not on another field. Neumann and Robin conditions are written with NormalDerivative(Γ), with any conormal coefficient written explicitly. Neumann and Robin data may depend on time; the Robin coefficient multiplying u(t, Γ) may depend only on space and parameters.
  • Periodic conditions u(t, Γa) ~ u(t, Γb) are rejected. Interface conditions between regions have no syntax; every field lives on the whole mesh.
  • Boundary pieces must be disjoint and lie on the boundary. Boundary facets with no condition for a field get the natural zero-flux condition, with a warning when that field's equation has a flux; natural declares them and boundary_check makes the warning an error or turns it off.
  • Where two Dirichlet pieces of one field meet, the condition listed last in the PDESystem wins.
  • Every field with a time derivative needs an initial condition, linear in that one field and finite at every node.
  • Time-dependent mass or stiffness coefficients and codegen = :mtk are rejected.

Multi-field systems, unequal orders and regions

Each dependent variable is one field with its own interpolation, given in spaces; fields without an entry get Lagrange{RefShape, 1}(). All fields share one quadrature rule, of order 2p for the highest order p unless quadrature is given. A Taylor–Hood Stokes system pairs a quadratic velocity with a linear pressure:

@variables x y u1(..) u2(..) p(..)
Δ(f) = Dx(Dx(f)) + Dy(Dy(f))
continuity = 0 ~ Dx(u1(t, x, y)) + Dy(u2(t, x, y))
eqs = [
    Dt(u1(t, x, y)) ~ Δ(u1(t, x, y)) - Dx(p(t, x, y)) + f1,
    Dt(u2(t, x, y)) ~ Δ(u2(t, x, y)) - Dy(p(t, x, y)) + f2,
    continuity,
]
P2, P1 = Lagrange{RefTriangle, 2}(), Lagrange{RefTriangle, 1}()
disc = FEMDiscretization(Ω, t; spaces = Dict(u1 => P2, u2 => P2, p => P1), pairing = Dict(continuity => p))

The continuity equation has no time derivative and no pressure, so pairing names the field it is tested with. The pressure rows are algebraic, and with Dirichlet velocity on the whole boundary the pressure is fixed only up to a constant: give it a Dirichlet condition on one small piece (a single facet set), or leave an outflow piece with the natural condition.

The pressure is absent from its own rows, so the DAE has index 2. Two things make DFBDF step it: start from a velocity that is discretely divergence free (zero, with zero Dirichlet data at the initial time) and a pressure initial condition, and leave the algebraic rows out of the error control with a large absolute tolerance on them, since the pressure's local error does not shrink with the step. FEMDiscretization does the second by default: with algebraic_abstol = :auto it detects an algebraic field absent from its own equation and gives the problem the abstol vector 1e8 on every algebraic row (the algebraic fields and the Dirichlet rows of all fields) and 1e-6 elsewhere:

prob = discretize(pdesys, disc)        # prob.kwargs[:abstol] is the vector
sol = solve(prob, DFBDF(nlsolve = NLNewton(new_W_dt_cutoff = 0)); reltol = 1.0e-8)

A number abstol given to FEMDiscretization or discretize sets the differential rows' entries, as in discretize(pdesys, disc; abstol = 1.0e-8); an array is used as it is. algebraic_abstol = 1.0e4 sets another value on the algebraic rows, of any system, and algebraic_abstol = nothing sets none. An abstol passed to solve replaces the whole vector (SciMLBase merges the problem's keywords first and the solve keywords over them), so solve(prob, alg; abstol = 1.0e-8) puts the algebraic rows back under error control; write the vector by hand in that case, abstol = [d ? 1.0e-8 : 1.0e8 for d in prob.differential_vars]. Systems without an index-2 field, such as 0 ~ Δv + u paired with v, get no abstol. The keyword applies to the time-dependent (DAE) path only: a steady FEMDiscretization(Ω) accepts :auto and nothing and does nothing with them, and raises for a number.

Without the large tolerance, the step size collapses near the initial time (dt below eps at t ≈ 1e-10 on a 16 × 16 Taylor–Hood mesh). When the linear solver then reports the Newton matrix as singular, LinearSolve falls back to a sparse QR factorization, which can take minutes and tens of gigabytes on a saddle-point system.

algebraic_abstol is not in the spec (§7.1, §7.6 list the FEMDiscretization keywords without it): it was added after the Taylor–Hood Stokes and DFG cylinder benchmarks needed the tolerance in user code every time.

A field can live on part of the mesh: regions = Dict(w => Region(Ω, :name)) restricts w to the cell set name, through a Ferrite SubDofHandler. Outside its region the field has no dofs, its equation is not assembled, it enters the other equations as zero, and the solution reads NaN there (sol[w(t, x, y)] at vertices outside the region, sol(t, x, y; dv) at points outside it). Its boundary conditions must be on pieces whose facets belong to the region's cells; on the rest of the region's boundary, such as an interface with the other cells, it has the natural zero-flux condition.

Streamline-upwind Petrov–Galerkin

test_space = SUPG(τ) (SUPG) tests every equation with v + τ b·∇v on every cell, where b is the advection velocity read from the equation (the coefficient of ∇u), or SUPG(τ; b = [b1, b2]). τ is a number, an expression, or a function τ(hK, b) of the cell diameter hK and b:

eq = Dt(u(t, x)) ~ ε * Dx(Dx(u(t, x))) - Dx(u(t, x))
τ(hK, b) = (Pe = abs(b[1]) * hK / (2ε); hK / (2abs(b[1])) * (coth(Pe) - 1 / Pe))
disc = FEMDiscretization(Ω, t; test_space = SUPG(τ))

The stabilisation is consistent: the strong residual, time derivative and source included, is tested with τ b·∇v, which needs the shape-function Hessians, so the CellValues are built with them. Limits: linear terms only, τ and b must be numbers or expressions in the coordinates, time and hK (not parameters of the PDESystem), and boundary terms stay Galerkin.

Curved meshes

The geometry of every cell comes from the mesh: the space, the assembly (facet normals included) and the solution interface map each cell with the geometric interpolation of its Ferrite cell type. A second-order mesh therefore gives curved cells with no option to set. To keep P2 at its full rate on a curved domain, mesh it at order 2 so the mid-side nodes lie on the true boundary:

using FerriteGmsh, Gmsh

Gmsh.initialize()
gmsh.option.setNumber("Mesh.MeshSizeMax", 0.05)
outer, inner = gmsh.model.occ.addCircle(0, 0, 0, 1.0), gmsh.model.occ.addCircle(0, 0, 0, 0.5)
surface = gmsh.model.occ.addPlaneSurface([gmsh.model.occ.addCurveLoop([outer]), gmsh.model.occ.addCurveLoop([inner])])
gmsh.model.occ.synchronize()
gmsh.model.addPhysicalGroup(1, [inner], -1, "inner")
gmsh.model.addPhysicalGroup(1, [outer], -1, "outer")
gmsh.model.addPhysicalGroup(2, [surface], -1, "domain")
gmsh.model.mesh.generate(2)
gmsh.model.mesh.setOrder(2)         # QuadraticTriangle cells, mid-side nodes on the circles
grid = FerriteGmsh.togrid()
Gmsh.finalize()

Ω = MeshDomain(grid)
Γi, Γo = boundarypiece.(Ω, (:inner, :outer))
disc = FEMDiscretization(Ω, t; spaces = Dict(u => Lagrange{RefTriangle, 2}()))

Conditions on the curved pieces are written as on any other piece, with NormalDerivative(Γ) the derivative along the outward normal of the curved facets. With straight-sided cells (setOrder(1)) the boundary is a polygon and P2 drops from L2 rate 3 to 2 once boundary data or normals of the true curve enter; test/shared/frontend_tests/curved.jl measures both on this annulus. Use a mesh generator that does not leave nodes outside every cell, such as the centre point of Gmsh's built-in-kernel circle arcs: sol[u] is NaN at such nodes.

Steady problems

A PDESystem with no time variable, discretized by a FEMDiscretization built without one, lowers to a NonlinearProblem K u + N(u) - F = 0, where N holds the terms whose coefficients depend on the state; without them Newton solves it in one step. Dirichlet rows are the algebraic equations u_d - g_d = 0, the Jacobian K + ∂N/∂u is sparse, and solve returns a PDENoTimeSolution with the same interface as a transient solution, without the time argument: sol[u(x, y)], sol(x, y; dv), traces sol[u(Γ)], derivatives such as sol[Dx(u(x, y))], normal_flux and write_vtk (one .vtu file). Traces are written u(Γ), since the dependent variables have no time argument.

using FiniteElementMethod, ModelingToolkit, NonlinearSolve
using Ferrite: Triangle
@variables x y u(..)
Dx, Dy = Differential(x), Differential(y)
Ω = MeshDomain(FiniteElementMethod.rectangle_grid(Triangle, (16, 16)))
eq = Dx(Dx(u(x, y))) + Dy(Dy(u(x, y))) ~ -1
@named pdesys = PDESystem([eq], [u(Γ) ~ 0 for Γ in boundarypieces(Ω)], [(x, y) ∈ Ω], [x, y], [u(x, y)], [])
prob = discretize(pdesys, FEMDiscretization(Ω))
sol = solve(prob, NewtonRaphson())
sol(0.5, 0.5; dv = u(x, y))

Newton starts from zero, with the Dirichlet data on any Dirichlet dofs the unknown vector holds; another initial guess is a vector laid out like prob.u0, passed as remake(prob; u0). With the default dirichlet = :algebraic that vector holds every dof and field name occupies FiniteElementMethod.field_range(prob.problem_type.space, name). Equations with no entry in pairing are tested with the remaining dependent variables in declared order. algebraic_abstol belongs to the time-dependent (DAE) path: a steady discretization accepts :auto and nothing and does nothing with them, and raises for a number.

Dirichlet conditions

dirichlet = :algebraic (the default) keeps every dof as an unknown and makes each prescribed row the algebraic equation u_d = g_d(t), so it accepts Dirichlet data of any time dependence. dirichlet = :eliminate removes the prescribed dofs instead: the DAEProblem has only the free dofs as unknowns, with M[fr, fr], K[fr, fr] and the load F[fr] - K[fr, cd] g; nonlinear terms are evaluated at the full state with u_cd = g and keep their rows fr. It needs Dirichlet data that are constant in time, though they may vary in space; time-dependent data raise an ArgumentError naming the boundary piece. The solution is the same either way: sol[u], sol(t, x, y), traces sol[u(t, Γ)], normal_flux and write_vtk all return the full field with g at the prescribed nodes. Only sol.original_sol and the array unknowns hold the free dofs alone.

disc = FEMDiscretization(Ω, t; dirichlet = :eliminate)
