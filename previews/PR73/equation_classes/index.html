Supported equation classes

This page states which classes of equations the package supports and on what evidence. The table is reproduced verbatim from the design specification (§1.1). Its evidence column cites the specification's verification runs: "report N" is a numbered prototype or library report, "red cell" is the independent re-run of those prototypes, and heat_1d1, convdiff2 and similar names are systems of the PDESystemLibrary corpus. "VERIFIED" means a run supports the claim; "INFERRED" means the claim was made by reading code or by extrapolation, without a run.

The library run behind most rows is narrower than its headline suggests: 392 of its 427 systems are one random-coefficient advection family. The honest figures are 9 of the library's 12 distinct PDE families accepted by the front end and 7 of 7 attempted systems solved end to end at nodal convergence rate about 2. The library exercises only time-dependent problems, mostly 1D, with MethodOfLines endpoint-form conditions on boxes; it has no Robin condition, no mesh domain, no second time derivative, no integral term, nothing in 3D and nothing steady (3D heat and steady problems are covered by the package's own tests).

The "Unstructured and Gmsh meshes" row's solve on a Gmsh mesh is the API example of Getting started, which the test suite runs (test/Frontend/api_example.jl).

Unstabilised Galerkin is centred differencing

The Galerkin method without stabilisation behaves like a centred finite-difference scheme: it is second-order accurate and non-dissipative. For Tier 2 problems (pure advection, advection-dominated and inviscid hyperbolic problems) it therefore produces oscillations at steep fronts and loses accuracy when the cell Péclet number exceeds one. The front end accepts these problems, but their results are not reliable with Galerkin testing. Use streamline-upwind Petrov–Galerkin stabilisation, test_space = SUPG(τ) (see SUPG).

The "not evidenced" row is neither a claim nor a rejection: nothing in any test or prototype covers discontinuous coefficients across interfaces. A row moves only when a test covers it.

Some rows are wider than this release. The table describes the design, so it lists classes that the front end of this release still rejects with an error, such as time-dependent mass or stiffness coefficients. Boundary conditions and limitations lists what this release accepts.
